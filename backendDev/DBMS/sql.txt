TYPES OF SQL COMMANDS: DDL, DQL, DML, DCL, TCL
1. DDL (data definition language): defining relation schema.
	1. CREATE: create table, DB, view.
	2. ALTER TABLE: modification in table structure. e.g, change column datatype or add/remove columns.
	3. DROP: delete table, DB, view.
	4. TRUNCATE: remove all the tuples from the table.
	5. RENAME: rename DB name, table name, column name etc.
2. DRL/DQL (data retrieval language / data query language): retrieve data from the tables.
	1. SELECT
3. DML (data modification language): use to perform modifications in the DB
	1. INSERT: insert data into a relation
	2. UPDATE: update relation data.
	3. DELETE: delete row(s) from the relation.
4. DCL (Data Control language): grant or revoke authorities from user.
	1. GRANT: access privileges to the DB
	2. REVOKE: revoke user access privileges.
5. TCL (Transaction control language): to manage transactions done in the DB
	1. START TRANSACTION: begin a transaction
	2. COMMIT: apply all the changes and end transaction
	3. ROLLBACK: discard changes and end transaction
	4. SAVEPOINT: checkout within the group of transactions in which to rollback.

mysql> create table worker(						//creating table
	worker_id int not null primary key auto_increment, 
	first_name char(25), 
	last_name char(25), 
	salary int(15), 
	joining_date datetime, 
	dept char(25)
        );

mysql> create table bonus(
	worker_ref_id int, 
	bonus_amount int(10), 
	bonus_date datetime, 
	foreign key(worker_ref_id) references worker(worker_id) on delete cascade  //foreign key with on delete cascade 
	);

mysql> create table title(
	worker_ref_id int, 
	worker_title char(25), 
	affected_from datetime, 
	foreign key(worker_ref_id) references worker(worker_id) on delete cascade
	);
__________________________________________________________________________________________________________________
CONSTRAINTS:
Auto_increment: increments the number foe each entry
Primary Key: PK is not null, unique and only one per table.
Foreign Key: FK refers to PK of other table. Each relation(table) can having any number of FK.
	     syntax : foreign key( col_name_of_fk ) references 	worker( col_name_of_the_pk_in_parent_table )
Not Null: ensures column cannot have a null value
Unique: Unique, can be null, table can have multiple unique attributes.
Default: Set default value of the column.
Check: a constraint to check the condition 
	eg:
		CHECK
	CREATE TABLE customer (
		...
		age INT,
		CONSTRAINT age_check CHECK (age > 12),	
		...
	);

MERGE: used to combine INSERT, UPDATE, and sometimes DELETE operations into a single statement. It is commonly used for synchronizing data between two tables.
mysql> MERGE INTO target_table AS target USING source_table AS source ON target.id = source.id
       WHEN MATCHED THEN UPDATE SET target.column = source.column
       WHEN NOT MATCHED THEN INSERT (columns) VALUES (values);
Eg:
MERGE INTO Employees E USING NewEmployees N ON E.ID = N.ID
WHEN MATCHED THEN
    UPDATE SET E.Salary = N.Salary
WHEN NOT MATCHED THEN
    INSERT (ID, Name, Salary)
    VALUES (N.ID, N.Name, N.Salary);

SUB QUERIES

1. Outer query depends on inner query
   A subquery is a query inside another query. The outer query uses the result returned by the inner query.
   Also known as Nested Queries - A query inside another query is called a nested query.
Example:
mysql> CREATE TABLE Employee (EmpID INT, EmpName VARCHAR(50),Salary INT);						//Create table
mysql> INSERT INTO Employee VALUES(1,'Alice',40000),(2,'Bob',60000),(3,'Carol',70000),(4,'David',50000);
Query:
mysql> SELECT * FROM Employee WHERE Salary >
	(
    		SELECT AVG(Salary) FROM Employee		//Inner query executes first returns 55000
	);
+-------+---------+--------+
| EmpID | EmpName | Salary |
+-------+---------+--------+
| 2     | Bob     | 60000  |
| 3     | Carol   | 70000  |
+-------+---------+--------+

Example using IN:
mysql> CREATE TABLE Customer(CustID INT,CustName VARCHAR(30));								//Create tables
mysql> INSERT INTO Customer VALUES(1,'Ram'),(2,'John'),(3,'Anu');
mysql> CREATE TABLE Orders(OrderID INT,CustID INT);
mysql> INSERT INTO Orders VALUES(101,1),(102,3);
Query:
mysql> SELECT * FROM Customer WHERE CustID IN
	(
    		SELECT CustID FROM Orders			//Inner query returns list of values - (1,3) 
	);
+--------+----------+
| CustID | CustName |
+--------+----------+
|      1 | Ram      |
|      3 | Anu      |
+--------+----------+

2. Alternative to JOINs
   Sometimes a subquery can produce the same result as a `JOIN`.
Example:
mysql> CREATE TABLE Department(DeptID INT, DeptName VARCHAR(30));							//Create tables
mysql> INSERT INTO Department VALUES(1,'HR'),(2,'IT'),(3,'Finance');
mysql> CREATE TABLE Employee( EmpID INT, EmpName VARCHAR(50), DeptID INT);
mysql> INSERT INTO Employee VALUES(101,'Alice',1),(102,'Bob',2),(103,'Carol',2),(104,'David',3);

+--------+----------+

+--------+----------+

Using a subquery:
mysql> SELECT EmpName FROM Employee WHERE DeptID =

	);
+---------+

+---------+

+---------+
The same result could also be obtained with an `INNER JOIN`.

4. Correlated Subqueries(Synchronised Query)
Unlike a normal subquery, a correlated subquery depends on the current row of the outer query. Therefore, it executes once for each row processed by the outer query.

mysql> CREATE TABLE Employee(EmpID INT,EmpName VARCHAR(30),DeptID INT,Salary INT);	//Create table
mysql> INSERT INTO Employee VALUES(1,'Alice',1,50000),(2,'Bob',1,60000),(3,'Carol',2,70000),(4,'David',2,65000),(5,'Eva',2,55000);
mysql> select * from Emp;
+-------+---------+--------+--------+
| EmpID | EmpName | DeptID | Salary |
+-------+---------+--------+--------+
|     1 | Alice   |      1 |  50000 |
|     2 | Bob     |      1 |  60000 |
|     3 | Carol   |      2 |  70000 |
|     4 | David   |      2 |  65000 |
|     5 | Eva     |      2 |  55000 |
+-------+---------+--------+--------+
Query:
mysql> SELECT EmpName, Salary FROM Employee E1 WHERE Salary >
	(
    		SELECT AVG(Salary) FROM Employee E2
   		WHERE E1.DeptID = E2.DeptID
	);
+---------+--------+
| EmpName | Salary |
+---------+--------+
| Bob     | 60000  |
| Carol   | 70000  |
| David   | 65000  |
+---------+--------+
Explanation:
For Alice (DeptID = 1):
	Average salary in Department 1 = (50000 + 60000) / 2 = 55000
	Alice's salary = 50000 → Not selected

For Bob (DeptID = 1):
	Average = 55000
	Bob's salary = 60000 → Selected

For Carol (DeptID = 2):
	Average salary in Department 2 = (70000 + 65000 + 55000) / 3 = 63333
	Carol's salary = 70000 → Selected

For David (DeptID = 2):
	65000 > 63333 → Selected

For Eva (DeptID = 2):
	55000 < 63333 → Not selected
---
Summary
| Type                          | Purpose                                                                      | Example                                                        |
| ----------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------- |
| WHERE subquery                | Filters rows based on the subquery result                                    | `WHERE Salary > (SELECT AVG(Salary)...)`                       |
| FROM subquery (Derived Table) | Creates a temporary table for the outer query                                | `FROM (SELECT ... ) AS Temp`                                   |
| SELECT subquery               | Returns a value displayed as a column                                        | `SELECT EmpName, (SELECT COUNT(*)...)`                         |
| Correlated subquery           | Executes once for each row in the outer query because it references that row | `WHERE Salary > (SELECT AVG(...) WHERE E1.DeptID = E2.DeptID)` |

INDEXING IN SQL:
The data entries(rows) are stored in blocks with a predefined size to it which holds some particular rows for each block
So when we want to read a row it have to load the entire block to memory 
This increases the time of execution 
INDEXING creates a new table with a column and its indexing pointing to the exact location in the actual table this is also stored in blocks in disk but it takes less blocks as it contains only 2 columns 
So to read a record first it have to read the index table and then read the particular blocks stated in the index table, this reduces the execution time significantly

Indexes slows down insert, update, delete process as its needs to be update the index table also

UNIQUE INDEXING: indexing for the column with unique constraint
A column with duplicate entries cannot be taken for unique indexing 
Even if the column is not unique while creating if the unique index in creating using that column it enforces the unique constraint on the column and do not allow duplicates
A unique index is used when you need two things at the same time:
	Fast searching (like a normal index sometimes more faster as it has only one record)
	A guarantee that duplicate values cannot exist

TRIGGERS: Special king of program that automatically executed when a specific event occurs in a table like insert, update, delete
Used in Automation like logging, business logics, automatically updating related data

NEW and OLD keywords:
+-------------------+--------------------+-----------------------------------------+
| Keyword           | Used In            | Meaning                                 |
+-------------------+--------------------+-----------------------------------------+
| `NEW.column_name` | `INSERT`, `UPDATE` | The new value being inserted or updated |
| `OLD.column_name` | `UPDATE`, `DELETE` | The existing value before the change    |
+-------------------+--------------------+-----------------------------------------+

Eg: before insert trigger
mysql> DELIMITER //
mysql> CREATE TRIGGER before_worker_insert					//creating trigger using a name
    -> BEFORE INSERT ON Worker						//condition when trigger is triggered
    -> FOR EACH ROW								//executes on each affected rows
    -> BEGIN
    ->     IF NEW.SALARY < 0 THEN						//logic to perform when triggered 
    ->         SET NEW.SALARY = 0;
    ->     END IF;
    -> END//
mysql> DELIMITER ;

TRANSACTIONS:
A transaction is a group of SQL operations that should succeed or fail together.
It is used to maintain data consistency.

Example: Bank transfer

mysql> BEGIN;
	UPDATE accounts SET balance = balance - 1000 WHERE account_id = 1;
	UPDATE accounts SET balance = balance + 1000 WHERE account_id = 2;
	COMMIT;

If the second UPDATE fails:
	ERROR: account_id 2 does not exist
PostgreSQL puts the transaction into a failed state. The first update is not permanently saved, but the transaction is still open. You need:

mysql> ROLLBACK;			//to cancel it.
