CONSTRAINTS

PRIMARY KEY      Uniquely identifies each row in a table.
                 Automatically enforces NOT NULL and UNIQUE.
                 A table can have only one primary key.
                 Example: id INT PRIMARY KEY
FOREIGN KEY      Ensures values in one table match values
                 in another table.
                 Maintains relationship between tables.
                 Example: customer_id INT REFERENCES customers(id)
UNIQUE           Ensures all values in a column or group
                 of columns are different.
                 Allows NULL values.
                 Example: email VARCHAR(100) UNIQUE
NOT NULL         Prevents a column from storing NULL values.
                 The column must always have a value.
                 Example: name TEXT NOT NULL
CHECK            Ensures values satisfy a specified condition
                 before insertion or update.
                 Example: age INT CHECK(age >= 18)
DEFAULT          Assigns a default value to a column when
                 no value is provided during insertion.
                 Example: status TEXT DEFAULT 'active'
EXCLUSION        Prevents rows from conflicting based on
                 a specified operator condition.
                 Commonly used for ranges and scheduling.
                 Example:EXCLUDE USING gist
                 (room WITH =, booking_time WITH &&)

Window Functions in PostgreSQL
A window function performs a calculation across a set of rows that are related to the current row, "without collapsing the rows".

The key difference:
GROUP BY combines rows into one row per group.
Window functions keep every row and add calculated information.

Example table: employees
| employee_id | first_name | team      | salary |
| ----------- | ---------- | --------- | ------ |
| 1           | Douglas    | Marketing | 97308  |
| 2           | Thomas     | Finance   | 61933  |
| 3           | Maria      | Finance   | 130590 |
| 4           | John       | Marketing | 85000  |

GROUP BY
pgsql>SELECT
    team,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY team;

Result:
| team      | avg_salary |
| --------- | ---------- |
| Marketing | 91154      |
| Finance   | 96261.5    |
The employee details disappear.

Window Function
pgsql>SELECT
    first_name,
    team,
    salary,
    AVG(salary) OVER(PARTITION BY team) AS team_avg
FROM employees;

Result:
| first_name | team      | salary | team_avg |
| ---------- | --------- | ------ | -------- |
| Douglas    | Marketing | 97308  | 91154    |
| John       | Marketing | 85000  | 91154    |
| Thomas     | Finance   | 61933  | 96261.5  |
| Maria      | Finance   | 130590 | 96261.5  |
The original rows remain.


Syntax:General form:
	function_name() OVER( PARTITION BY column ORDER BY column )
Example:
pgsql> select AVG(salary) OVER(PARTITION BY team) from employees;


1. ROW_NUMBER(): Assigns a unique number to each row.

pgsql> SELECT first_name, salary,
       ROW_NUMBER() OVER(
          ORDER BY salary DESC
       ) AS rank
       FROM employees;

Result:
| name    | salary | rank |
| ------- | ------ | ---- |
| Maria   | 130590 | 1    |
| Douglas | 97308  | 2    |
| Thomas  | 61933  | 3    |


2. RANK(): Ranks rows but leaves gaps when values are equal.

Example:
| name  | salary |
| ----- | ------ |
| Maria | 100000 |
| John  | 90000  |
| Alex  | 90000  |
| Bob   | 80000  |

Query:
pgsql> SELECT
       first_name, salary,
       RANK() OVER(
           ORDER BY salary DESC
       )
       FROM employees;

Result:
| name  | salary | rank |
| ----- | ------ | ---- |
| Maria | 100000 | 1    |
| John  | 90000  | 2    |
| Alex  | 90000  | 2    |
| Bob   | 80000  | 4    |

Notice rank 3 is skipped.

3. DENSE_RANK(): Same as rank but no gaps.

pgsql> SELECT
       first_name, salary,
       DENSE_RANK() OVER(
           ORDER BY salary DESC
       )
       FROM employees;

Result:
| name  | salary | rank |
| ----- | ------ | ---- |
| Maria | 100000 | 1    |
| John  | 90000  | 2    |
| Alex  | 90000  | 2    |
| Bob   | 80000  | 3    |

4. Ranking inside groups
Example:
Rank employees inside each team.

pgsql> SELECT
       first_name, team, salary,
       RANK() OVER(
           PARTITION BY team
           ORDER BY salary DESC
       ) AS team_rank
       FROM employees;

Result:
| name    | team      | salary | rank |
| ------- | --------- | ------ | ---- |
| Maria   | Finance   | 130590 | 1    |
| Thomas  | Finance   | 61933  | 2    |
| Douglas | Marketing | 97308  | 1    |
| John    | Marketing | 85000  | 2    |

`PARTITION BY` creates separate windows.

5. Running total
Example:
pgsql> SELECT
       first_name, salary,
       SUM(salary) OVER(
           ORDER BY employee_id
       ) AS running_total
       FROM employees;

Result:
| name    | salary | running_total |
| ------- | ------ | ------------- |
| Douglas | 97308  | 97308         |
| Thomas  | 61933  | 159241        |
| Maria   | 130590 | 289831        |

Each row sees previous rows.


6. LAG(): Access previous row.
Example:

pgsql> SELECT
       first_name, salary,
       LAG(salary) OVER(
           ORDER BY employee_id
       ) AS previous_salary
       FROM employees;

Result:
| name    | salary | previous_salary |
| ------- | ------ | --------------- |
| Douglas | 97308  | NULL            |
| Thomas  | 61933  | 97308           |
| Maria   | 130590 | 61933           |


7. LEAD(): Access next row.

pgsql> SELECT
       first_name, salary,
       LEAD(salary) OVER(
           ORDER BY employee_id
       ) AS next_salary
       FROM employees;

Result:
| name    | salary | next_salary |
| ------- | ------ | ----------- |
| Douglas | 97308  | 61933       |
| Thomas  | 61933  | 130590      |
| Maria   | 130590 | NULL        |

8. FIRST_VALUE(): Get first value in a window.

pgsql> SELECT
       first_name, team, salary,
       FIRST_VALUE(first_name)
       OVER(
           PARTITION BY team
           ORDER BY salary DESC
       ) AS highest_paid
       FROM employees;

Result:
| name    | team      | highest_paid |
| ------- | --------- | ------------ |
| Maria   | Finance   | Maria        |
| Thomas  | Finance   | Maria        |
| Douglas | Marketing | Douglas      |

9. LAST_VALUE(): Get last value in a window.

pgsql> SELECT
       first_name, salary,
       LAST_VALUE(first_name)
       OVER(
           ORDER BY salary
       )
       FROM employees;

10. NTILE(): Divide rows into groups.

Example: Divide employees into 4 salary groups.

pgsql>
SELECT
    first_name,
    salary,
    NTILE(4) OVER(
        ORDER BY salary
    ) AS salary_group
FROM employees;

# Window functions execution order

Logical SQL order:

```
FROM
 ↓
WHERE
 ↓
GROUP BY
 ↓
HAVING
 ↓
WINDOW FUNCTIONS
 ↓
SELECT
 ↓
ORDER BY
 ↓
LIMIT
```

This is why you cannot normally use a window function directly in `WHERE`.

Wrong:

```sql
SELECT *
FROM employees
WHERE RANK() OVER(ORDER BY salary)=1;
```

Correct:

```sql
SELECT *
FROM
(
    SELECT *,
    RANK() OVER(ORDER BY salary) r
    FROM employees
) x
WHERE r=1;
```

## Main PostgreSQL window functions to learn

| Category     | Functions                                                   |
| ------------ | ----------------------------------------------------------- |
| Ranking      | `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`                    |
| Navigation   | `LAG()`, `LEAD()`                                           |
| Value        | `FIRST_VALUE()`, `LAST_VALUE()`, `NTH_VALUE()`              |
| Aggregates   | `SUM()`, `AVG()`, `COUNT()`, `MIN()`, `MAX()` with `OVER()` |
| Distribution | `NTILE()`, `PERCENT_RANK()`, `CUME_DIST()`                  |

Window functions are one of the most important PostgreSQL topics for analytics, reporting, ranking, and data engineering.





CTE - A CTE (Common Table Expression) in PostgreSQL is a temporary, named result set that you define at the beginning of a query using the WITH keyword. It helps make complex SQL queries more readable and reusable.

Syntax:
WITH cte_name AS (
    SELECT ...
)
SELECT *
FROM cte_name;

It can be implemented using sub queries but more useful in complicated calculation that you need to use multiple times.

Using SUB-QUERY:
SELECT *
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);

Using CTE:
WITH avg_salary AS (
    SELECT AVG(salary) AS avg_sal
    FROM employees
)
SELECT *
FROM employees
WHERE salary > (
    SELECT avg_sal
    FROM avg_salary
);


Complex calculation using CTE:

WITH department_stats AS (
    SELECT
        department_id,
        AVG(salary) AS avg_salary,
        MAX(salary) AS max_salary
    FROM employees
    GROUP BY department_id
)
SELECT
    e.name,
    e.salary,
    d.avg_salary,
    d.max_salary
FROM employees e
JOIN department_stats d
    ON e.department_id = d.department_id
WHERE e.salary > d.avg_salary;


Multiple CTE:

WITH
department_avg AS (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
),
high_earners AS (
    SELECT *
    FROM employees e
    JOIN department_avg d
      ON e.department_id = d.department_id
    WHERE e.salary > d.avg_salary
)
SELECT *
FROM high_earners;



Triggers: In PostgreSQL, a trigger is a mechanism that automatically executes a function when a particular event happens on a table (or other database object).

First we need to create a trigger function:
CREATE OR REPLACE FUNCTION set_created_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.created_at := CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

Then create trigger:
CREATE OR REPLACE FUNCTION set_created_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.created_at := CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
